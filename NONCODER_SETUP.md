# Non-Coder Setup Guide

## What you need
1. A free GitHub account.
2. A free Supabase account/project.
3. A Vercel account if using Vercel deployment.
4. OpenCode installed and this project folder opened.

## Supabase
Create a new project. Obtain the project URL and the public/anon key. Store them only in the environment file as instructed by OpenCode. Never expose the service-role key in browser code.

## One-time step so you never paste SQL again

Until now, every database change meant copying a large file into the Supabase SQL Editor and pressing Run. That is done for you from now on, with one command: `npm run db:push`.

It needs permission to connect to your database, which means one thing copied once from the dashboard:

1. Supabase dashboard, your project, the gear icon, **Settings**, then **Database**.
2. Find the **Connection string** panel and the **URI** line. It looks like
   `postgresql://postgres:YOUR-PASSWORD@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`
3. Click the copy button at the end of that line.
4. Open `.env.local` in this project and add one line at the bottom:
   `DATABASE_URL=` followed by what you copied. Nothing else in that line is changed.

That is the only manual database step there is. After it, `npm run db:push` applies every change, is safe to run twice, and reports what it did. If you would rather not store the connection string, leave it out and the same command will simply ask you to paste the password when you run it, without saving it.

To see where your database stands without changing anything: `npm run db:push -- --check`.

## Local setup
Use the commands generated by OpenCode from the project's package manager. The README should contain the exact commands after scaffolding.

## Checking everything
`npm run test:all` runs every check in order and prints a single pass/fail summary: the content files, the migrations, the security rules, the progression engine, the objective exam, the theory exam and the study tools, all against your real database. If a check fails only because the connection dropped, it is retried for you before the run is called red.

## First administrator
Use the application's documented bootstrap/admin process. Do not hard-code administrator credentials in source files.

## Deployment
Push the project to GitHub, import it into Vercel, add the Supabase environment variables, deploy, then configure the Supabase authentication redirect URL to the production domain.

## Cost discipline
Avoid paid email, analytics, search, AI and storage providers unless explicitly enabled later. Prefer Supabase/Postgres capabilities and browser-native functionality for the initial release.
